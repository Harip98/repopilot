# M0 Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an empty but runnable RepoPilot skeleton:
- a Python `repopilot` package with settings and a migration CLI
- the first schema (runs, events, tool calls, approvals, eval results)
- a Go `sandbox-svc` that answers `/healthz`
- Postgres + Redis in compose
- CI that runs all of it

**Architecture:** This follows the ind-agent layout:
- `services/agent-svc` (uv, hatchling, Typer CLI, raw psycopg 3)
- `services/sandbox-svc` (Go stdlib `net/http`, slog JSON)
- `db/migrations/NNN_*.sql`, applied by a checksum-checked, advisory-locked runner copied from ind-agent

Nothing is agent-specific yet. This milestone only fixes names, ports, schema and CI so M1–M3 can build on them.

**Tech Stack:** Python 3.12, uv, pydantic-settings, psycopg 3.2, Typer, pytest, ruff; Go 1.25; `pgvector/pgvector:pg16`; `redis:7-alpine`; GitHub Actions.

**Spec:** [docs/plan.md](../plan.md), sections Decisions, Directory skeleton, Reuse from ind-agent, and M0.

## Global Constraints

- Python `requires-python = ">=3.12,<3.13"`. The package is `repopilot` and lives at `services/agent-svc/src/repopilot`. The console script is `repopilot = "repopilot.cli:app"`.
- Env prefix is `REPOPILOT_`. Settings come from the repo-root `.env`. The repo root is found by walking up to `docker-compose.yml`.
- Ports avoid ind-agent's, so both stacks can run at once:
  - Postgres `127.0.0.1:5434`
  - Redis `127.0.0.1:6380`
  - sandbox-svc `127.0.0.1:8090`
  - (agent API `127.0.0.1:8000` is reserved for M5)
- Use `127.0.0.1`, never `localhost`, because Docker binds IPv4 only.
- Database `repopilot`, user `repopilot`, dev password `repopilot_dev_pw`. Integration tests use the database `repopilot_test`.
- Ruff `line-length = 100`, `target-version = "py312"`. Tests marked `integration` are skipped unless the run uses `-m integration`.
- Go module path is `repopilot/sandbox-svc`, on Go 1.25.
- Commits use conventional prefixes (`feat(db):`, `chore:`, `ci:`).
- `.gitattributes` sets `* text=auto eol=lf`. This is a Windows dev box, and migration checksums must not depend on line endings.

## Review Focus

1. **A migration file is edited after it was applied.** `migrate` must refuse with `MigrationChecksumError` and apply nothing. Test: `test_edited_migration_rejected` (Task 2).
2. **A CRLF checkout of an already-applied migration.** It must be treated as unchanged, because the checksum normalises `\r\n`. Test: `test_crlf_checksum_matches_lf` (Task 2).
3. **`repopilot migrate` is run twice.** The second run applies nothing and exits 0. Test: `test_migrate_idempotent` (Task 2, integration).
4. **The CLI is run from a subdirectory, or with no `.env` present.** Repo root is still found, defaults apply, and env vars override them. Tests: `test_find_repo_root_from_subdir` and `test_env_overrides` (Task 1).
5. **A run row gets an unknown status, or an eval result is recorded twice for the same task in one eval run.** The database rejects it. Tests: `test_run_status_check` and `test_eval_result_unique` (Task 2, integration).

### Task 2: Migration runner and the 001 schema

**Files:**

- Test:
  - `tests/db/test_migrate.py` (unit)
  - `tests/integration/conftest.py`
  - `tests/integration/test_schema.py`

**Interfaces:**
- Consumes: `Settings.dsn()` and `REPO_ROOT` from Task 1.
- Produces:
  - `repopilot.db.migrate.discover(dir: Path) -> list[tuple[str, Path]]`
  - `apply_migrations(conn, migrations_dir=MIGRATIONS_DIR) -> list[str]`
  - `MigrationChecksumError`
  - `MIGRATIONS_DIR = REPO_ROOT / "db" / "migrations"`
  - CLI `repopilot migrate`, which prints applied versions or "up to date"
  - Integration fixture `settings` (session-scoped), pointing at `repopilot_test` and migrated
  - Fixture `conn` (autocommit, per test), which cleans the five tables after each test

**001_runs.sql:**
- `runs`:
  - `id uuid PK DEFAULT gen_random_uuid()`
  - `task_id text`
  - `repo text NOT NULL`
  - `issue_ref text`
  - `issue_text text NOT NULL`
  - `status text NOT NULL DEFAULT 'queued'`, CHECK in (`queued`, `running`, `awaiting_approval`, `approved`, `rejected`, `pr_opened`, `failed`, `cancelled`)
  - `model text`
  - `retries int NOT NULL DEFAULT 0`
  - `prompt_tokens int NOT NULL DEFAULT 0`
  - `completion_tokens int NOT NULL DEFAULT 0`
  - `cost_usd numeric(12,6) NOT NULL DEFAULT 0`
  - `pr_url text`
  - `trace_id text`
  - `error text`
  - `created_at` / `updated_at timestamptz NOT NULL DEFAULT now()`
  - `finished_at timestamptz`
- `run_events`:
  - `id bigserial PK`
  - `run_id uuid NOT NULL REFERENCES runs ON DELETE CASCADE`
  - `seq int NOT NULL`
  - `node text NOT NULL`
  - `kind text NOT NULL`
  - `payload jsonb NOT NULL DEFAULT '{}'`
  - `created_at`
  - `UNIQUE(run_id, seq)`
- `tool_calls`:
  - `id bigserial PK`
  - `run_id` (FK, cascade)
  - `step int NOT NULL`
  - `tool text NOT NULL`
  - `args jsonb NOT NULL`
  - `ok bool NOT NULL`
  - `denied bool NOT NULL DEFAULT false`
  - `result_excerpt text`
  - `error text`
  - `latency_ms int NOT NULL`
  - `created_at`
  - index `(run_id, step)`
- `approvals`:
  - `id bigserial PK`
  - `run_id` (FK, cascade)
  - `decision text NOT NULL CHECK (decision IN ('approve','reject'))`
  - `comment text`
  - `decided_by text NOT NULL`
  - `created_at`
- `eval_results`:
  - `id bigserial PK`
  - `eval_run text NOT NULL`
  - `task_id text NOT NULL`
  - `run_id uuid REFERENCES runs ON DELETE SET NULL`
  - `model text NOT NULL`
  - `resolved`, `patch_applied`, `visible_tests_passed`: `bool NOT NULL`
  - `retries`, `tool_calls`, `tool_failures`, `unauthorized_attempts`, `latency_ms`, `prompt_tokens`, `completion_tokens`: `int NOT NULL`
  - `cost_usd numeric(12,6) NOT NULL`
  - `created_at`
  - `UNIQUE(eval_run, task_id)`
