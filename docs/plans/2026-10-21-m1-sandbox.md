# M1 Sandbox Implementation Plan

> The plan as written before implementation, kept as design history; its checkboxes were not used for tracking. [README.md](../../README.md) and [architecture.md](../architecture.md) describe the system as built.

**Goal:** Build a hardened sandbox that `sandbox-svc` creates and controls, and that agent-svc uses through an authenticated REST API. In each sandbox, the agent can upload a repo, read and write files, and run allowlisted commands. Integration tests must prove that the sandbox has no network, no writes outside the workspace, contained fork bombs, timeouts that fire, and capped output.

**Architecture:**
- `sandbox-svc` runs in compose with `/var/run/docker.sock` mounted. It is the only process that holds the socket.
- It talks to the Docker Engine API through a small hand-written client:
  - transport: HTTP over the unix socket
  - paths: unversioned, so the daemon uses its own current API version
  - dependencies: none
- Each sandbox is one long-lived container running `sleep infinity`. Its `/workspace` is a size-capped tmpfs volume owned by uid 10001.
- Commands run via exec, wrapped in coreutils `timeout`. If the exec stream outlives the deadline, the container is restarted as a backstop.
- Files cross the boundary through the archive API (`PUT` with `copyUIDGID=true`, `GET` for reads), so no shell quoting is involved.

The M1 spike (2026-10-21) verified on Docker 29.2.1 that:
- a tmpfs volume with `uid=10001` works with a read-only rootfs
- archive copy with copyUIDGID gives 10001-owned writable files; without it, files are root-owned and unwritable
- `--network none` gives ENETUNREACH
- `timeout` returns 124

**Tech Stack:** Go 1.25 stdlib only (`net/http` over a unix socket, `archive/tar`). Python async `httpx`. Docker Engine API.

**Spec:** [docs/plan.md](../plan.md), sections Decisions ("Go's role"), Architecture ("Sandbox lifecycle") and M1.

## Global Constraints

- **Hardening.** Every sandbox container is created with:
  - `NetworkMode: "none"`
  - `CapDrop: ["ALL"]`
  - `SecurityOpt: ["no-new-privileges:true"]`
  - `ReadonlyRootfs: true`
  - `User: "10001:10001"`
  - `Init: true`
  - `IpcMode: "private"`
  - `Privileged: false`
  - `Memory` = `MemorySwap` = 1 GiB
  - `NanoCpus` = 1e9
  - `PidsLimit` = 256
  - `Tmpfs {"/tmp": "rw,nosuid,nodev,size=256m"}`
  - env `HOME=/tmp` and `PYTHONDONTWRITEBYTECODE=1`
  - exactly one mount: the volume at `/workspace`

  Nothing else is mounted, the Docker socket in particular.
- **Workspace volume.** Driver `local`, opts `type=tmpfs`, `device=tmpfs`, `o=size=512m,uid=10001,gid=10001`.
- **Naming.** Volumes are `rp-ws-<id>` and containers `rp-sbx-<id>`. `<id>` is 16 lowercase hex characters from `crypto/rand`. Labels are `repopilot.sandbox=1` and `repopilot.created=<unix seconds>`.
- **Images.** Only images whose name starts with a prefix in `SANDBOX_IMAGE_PREFIXES` (comma-separated, default `repopilot-`; *as built:* `repopilot-sandbox-,repopilot-bench-`, so the agent's own image is refused) may be used. Anything else gets 400 `image_not_allowed`.
- **Exec argv.**
  - `argv[0]` must be in `git, rg, python, python3, pytest, ruff, ls, cat, head, tail, wc, find, diff`. Anything else gets 400 `command_not_allowed`.
  - No shells.
  - At most 64 args, and at most 32 KiB in total.
  - `timeout_s` defaults to 120 and is clamped to 1..600.
  - The command runs as `["timeout", "-k", "5", "<N>s", ...argv]`, in `/workspace` or in a validated relative `cwd`.
  - The allowlist is defence in depth. The container is the boundary. The README must say so.
- **Output caps.** stdout and stderr are capped at 64 KiB each. Bytes past the cap are drained and discarded, and the matching `*_truncated` flag is set. Output is returned as valid UTF-8 (invalid bytes are replaced).
- **Size caps.** File reads and writes are capped at 1 MiB (413 `too_large`). Repo upload is capped at 256 MiB.
- **Paths.** A path must be relative, non-empty, without NUL or `\`, and `path.Clean` must not start with `..`. Violations get 400 `bad_path`. Reading a non-regular file (dir or symlink) gets 400 `not_a_file`. A missing file gets 404 `not_found`.
- **Auth.** Every route except `GET /healthz` needs `Authorization: Bearer $SANDBOX_TOKEN`, compared in constant time. Otherwise the response is 401 `unauthorized`. The service refuses to start if `SANDBOX_TOKEN` is shorter than 16 characters.
- **Reaper.** Sandboxes older than `SANDBOX_TTL` (default `2h`) are removed every minute. This includes orphans from a previous process, found by label.
- **Errors.** Every error body is `{"error":{"code","message"}}`.
- **Compose.** Add a `sandbox-svc` service:
  - `user: "0:0"` (socket access; documented as root-equivalent)
  - `read_only: true`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`
  - port `127.0.0.1:8090:8090`
  - env `SANDBOX_TOKEN: ${REPOPILOT_SANDBOX_TOKEN:-dev-sandbox-token-change-me}`

  agent-svc's `Settings.sandbox_token: SecretStr` has the same default.
- **Base sandbox image.** `repopilot-sandbox-base`, built from `bench/images/base/Dockerfile`:
  - `python:3.12-slim` plus `git`, `ripgrep` and `pytest`
  - user 10001
  - `git config --system safe.directory '*'`
  - workdir `/workspace`
  - entrypoint `sleep infinity`

## Review Focus

1. **A repo contains a symlink to `/etc/passwd`, or to a path outside `/workspace`.** Reading it gives `not_a_file`, never the target's content. Test: `test_symlink_read_rejected` (Task 4, sandbox integration).
2. **The exec HTTP request outlives the server's `WriteTimeout`.** M0 had a fixed 30s. The exec handler must extend its own write deadline (`http.ResponseController.SetWriteDeadline`) to timeout + 30s. Test: `TestExecExtendsWriteDeadline` (Task 3).
3. **sandbox-svc restarts with sandboxes still running.** The reaper removes expired orphans by label, and fresh ones survive. Test: `TestReaperRemovesExpiredOnly` (Task 2).
4. **A huge or binary output, e.g. `cat` of a 50 MB file.** Each stream is capped, the response stays small, the bytes are valid UTF-8, and the flag is set. Tests: `TestDemuxCapsAndDrains` (Task 1) and `test_output_truncated` (Task 4).
5. **An unclean path like `//nope`.** The router returns 404 JSON, not a 301 without `Location` (M0 deferred minor). Test: a row in `TestServerRoutes` (Task 3).

### Task 3: HTTP API, auth, main and compose

- Consumes: Task 2's `Manager` methods, through an interface `Sandboxes` (fake in tests).
- Produces:
  - `NewServer(logger, sb Sandboxes, token string) http.Handler`
  - Routes (JSON unless noted):
    - `GET /healthz`
    - `POST /v1/sandboxes` `{image}` → 201 `{id}`
    - `PUT /v1/sandboxes/{id}/archive` (body `application/x-tar`) → 204
    - `GET /v1/sandboxes/{id}/file?path=` → 200 raw bytes (`application/octet-stream`)
    - `PUT /v1/sandboxes/{id}/file?path=` (raw body, max 1 MiB) → 204
    - `POST /v1/sandboxes/{id}/exec` `ExecRequest` → 200 `ExecResponse`
    - `DELETE /v1/sandboxes/{id}` → 204
  - Error mapping:
    - `ErrImageNotAllowed`/`ErrCommandNotAllowed`/`ErrBadPath`/`ErrNotAFile`/`ErrBadArgv` → 400 with codes `image_not_allowed`, `command_not_allowed`, `bad_path`, `not_a_file`, `bad_argv`
    - `ErrNotFound` → 404 `not_found`
    - `ErrTooLarge` → 413 `too_large`
    - otherwise → 500 `internal`, with the message hidden and the error logged
  - `{id}` must match `^[0-9a-f]{16}$`, otherwise 404.
