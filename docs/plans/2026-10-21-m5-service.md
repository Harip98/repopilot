# M5 Service Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run RepoPilot as a service.
- An authenticated async API creates runs, from a benchmark task or a GitHub issue, and streams their timeline over SSE.
- Approval is accepted over HTTP.
- A worker executes runs from a durable Redis Streams queue and reclaims jobs from crashed workers.
- An approved GitHub run becomes a **draft pull request**, built with the Git Data API on the host. The token never enters the sandbox.

**Architecture:**
- `repopilot.api` (FastAPI) writes the run row and enqueues a job. It never runs the agent itself.
- `repopilot.queue` wraps Redis Streams:
  - stream `repopilot:jobs`, group `workers`;
  - `XADD`, then `XREADGROUP`, then `XACK`;
  - `XAUTOCLAIM` for entries idle longer than the visibility timeout.
- `repopilot.worker` consumes `start` and `resume` jobs, using the M3 runner for both. Because LangGraph checkpoints every step, a redelivered `start` job continues the run from its checkpoint instead of starting over. Status checks make every job idempotent.
- `repopilot.github` (httpx) handles four things:
  - reads issues;
  - downloads the repository tarball and extracts it with `tarfile`'s `data` filter;
  - builds the import workspace;
  - opens draft PRs through blobs, tree, commit, ref and pull.
- Configuration in the target repo: `.repopilot.yml` sets `test_command` and `image`. The defaults are `pytest -q` and `repopilot-sandbox-base`.

**Tech Stack:** FastAPI ≥ 0.115 with uvicorn; `redis` ≥ 5 (asyncio); `sse-starlette` is not needed, since SSE is a plain `StreamingResponse`; httpx; the M3 runner and recorder.

**Spec:** [docs/plan.md](../plan.md), sections Decisions (Queue, GitHub) and M5.

## Global Constraints

- **API surface.** Every `/v1` route needs `Authorization: Bearer $REPOPILOT_API_TOKEN`, compared in constant time; `/healthz` does not. The routes:
  - `POST /v1/runs`, with body `{"task_id": "orders-api-005"}` **or** `{"repo": "owner/name", "issue_number": 42}`, plus optional `"auto_approve": false`. Returns `202 {"run_id", "status": "queued"}`.
  - `GET /v1/runs?limit=50`
  - `GET /v1/runs/{id}`: the run row, plus `plan`, `summary`, `diff`, `tests` and `approval_request` from the newest `approval/awaiting` event.
  - `GET /v1/runs/{id}/events`: SSE. Each event is `id: <seq>`, `event: <node>.<kind>`, `data: <json>`. It honours `Last-Event-ID`, polls Postgres every second, sends a keep-alive comment every 15 s, and closes after a terminal status.
  - `GET /v1/runs/{id}/tool-calls`
  - `POST /v1/runs/{id}/approval`, body `{"decision": "approve"|"reject", "comment"?}`. It claims the run atomically (M3 `claim_for_approval`), then enqueues `resume` and returns 202. If the run is not awaiting approval it returns `409 {"error": {"code": "not_awaiting_approval"}}`.
  - `GET /v1/evals` and `GET /v1/evals/{name}`, which return the summary and rows from `PgResultStore`.
- **Errors.** Every error body is `{"error":{"code","message"}}`. Every response carries `X-Trace-Id` and the security headers adapted from ind-agent `api.py`. CORS allows only `REPOPILOT_UI_ORIGIN`, default `http://127.0.0.1:3000`.
- **Jobs.** `{"type": "start"|"resume", "run_id", ...}` as JSON in the stream field `job`. The visibility timeout is 30 min (`REPOPILOT_JOB_VISIBILITY_S`). A job delivered more than 3 times is marked failed with `failure_reason="job_retries_exhausted"` and acked.
- **Approval checkpoint.** The approval node records `event(run_id, "approval", "awaiting", payload)` before it interrupts. This is the API's source for `approval_request`.
- **GitHub mode.**
  - **Workspace:** a tarball of the default branch's head is extracted, then `git init` and commit `Import owner/name@<sha12>`.
  - **Protected paths:** the M2 defaults plus `.github/**` (already always protected).
  - **Branch:** `repopilot/<run_id[:8]>`.
  - **Pull request:** title `RepoPilot: <issue title> (#N)`, with `draft: true`. The body holds the summary, the plan, the test result and `Fixes #N`.
  - `runs.issue_ref` is `owner/name#N` and `runs.pr_url` is set.
- **Settings added:** `api_token: SecretStr`, `ui_origin`, `job_visibility_s=1800`, `github_api_url="https://api.github.com"`.
- **Container-safe config.** `REPO_ROOT` resolution falls back to `REPOPILOT_ROOT`, then to the working directory, when `docker-compose.yml` is not found (M0 deferred minor). Compose gets an `app` profile with the `api` and `worker` services.
- **Scope limit, documented in the README.** GitHub runs need tests that run in the configured sandbox image. There is no networked dependency install yet.

## Review Focus

1. **A worker dies mid-run.** Another worker reclaims the job after the visibility timeout and continues from the checkpoint. Completed tool calls are not repeated. Test: `test_reclaimed_start_continues_from_checkpoint` (Task 1).
2. **The same approval is POSTed twice concurrently.** One 202 and one 409; exactly one `resume` job. Test: `test_approval_exclusive` (Task 2).
3. **The SSE client reconnects with `Last-Event-ID`.** No duplicated or skipped events. Test: `test_events_resume_from_last_id` (Task 2).
4. **A GitHub tarball contains `../` paths, symlinks out of the tree, or absolute names.** Extraction refuses them through the `data` filter and the run fails cleanly. Test: `test_tarball_extraction_is_safe` (Task 3).
5. **A PR is opened for a change that deletes or renames files.** The tree marks deleted paths with `sha: null`, and renames appear as delete plus add. Test: `test_pr_tree_includes_deletions` (Task 3).
